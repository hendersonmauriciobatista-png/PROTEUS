# Guia De Publicacao Futura Do Website Institucional Do PROTEUS

## Objetivo

Documentar recomendacoes para uma futura publicacao institucional do Website Oficial do PROTEUS.

Esta PD nao realiza implantacao, nao cria frontend, nao configura hospedagem e nao publica dominio.

## Principios De Publicacao

* Preservar identidade visual oficial.
* Publicar apenas conteudo validado.
* Separar website institucional de aplicacao desktop.
* Nao expor dados operacionais reais.
* Nao publicar contatos pessoais.
* Manter rastreabilidade com documentos oficiais.

## Alternativas De Hospedagem

### GitHub Pages

Uso recomendado:

* website estatico simples;
* publicacao integrada ao repositorio;
* documentacao institucional em Markdown ou site estatico.

Vantagens:

* baixo custo;
* boa rastreabilidade;
* adequado para documentacao publica;
* integracao natural com GitHub.

Atencoes:

* exige cuidado com exposicao de arquivos internos;
* nao deve publicar dados operacionais sensiveis;
* dominio customizado exige configuracao adicional.

### Vercel

Uso recomendado:

* site institucional estatico ou gerado por framework frontend em etapa futura propria.

Vantagens:

* deploy simples;
* boa experiencia para sites modernos;
* suporte a dominio proprio.

Atencoes:

* uma implementacao futura deve ser aprovada antes;
* nao usar funcoes backend sem PD/GP propria;
* evitar dependencias desnecessarias para site institucional simples.

### Netlify

Uso recomendado:

* site estatico institucional;
* publicacao de documentacao ou paginas publicas simples.

Vantagens:

* fluxo simples de deploy;
* suporte a formularios em planos especificos;
* suporte a dominio proprio.

Atencoes:

* formularios de contato exigem politica de dados;
* automacoes devem ser documentadas;
* publicar somente conteudo aprovado.

### Dominio Proprio

Uso recomendado:

* consolidacao institucional publica do PROTEUS.

Vantagens:

* reforca identidade institucional;
* facilita comunicacao em apresentacoes;
* permite URL oficial.

Atencoes:

* exige decisao institucional;
* exige gestao de DNS;
* exige governanca de responsaveis;
* exige padrao de seguranca e renovacao.

## Recomendacao Documental

Para primeira publicacao futura, a alternativa mais simples tende a ser site estatico com documentacao versionada, preferencialmente com GitHub Pages ou plataforma equivalente.

Essa recomendacao nao representa implantacao nem decisao tecnica obrigatoria.

## Checklist Previo A Publicacao

* Revisar conteudo institucional.
* Validar identidade visual.
* Confirmar ausencia de dados pessoais.
* Confirmar ausencia de dados operacionais reais sensiveis.
* Revisar links de documentacao.
* Validar responsavel institucional pelo canal.
* Definir politica de contato antes de qualquer formulario funcional.

## Veredito

A publicacao futura deve priorizar simplicidade, rastreabilidade e coerencia institucional, sem transformar o website em aplicacao operacional.
